# Прототип гибридной системы семантического поиска

Настоящий репозиторий содержит программный прототип гибридной системы семантического поиска, предназначенный для проведения вычислительных экспериментов в рамках выпускной квалификационной работы. Реализация объединяет плотные векторные представления текстов, адаптивное бинарное хэширование, приближённый поиск кандидатов и последующее точное повторное ранжирование найденных документов.

Репозиторий ориентирован на воспроизводимое исследование полного цикла обработки данных:

- подготовка корпуса и обучающих выборок;
- обучение бинарного хэширующего модуля;
- построение поискового индекса;
- выполнение поиска;
- оценка качества;
- сохранение артефактов эксперимента.

## Аннотация

В задачах семантического поиска широко применяются плотные эмбеддинги и методы приближённого поиска ближайших соседей. Данный подход обеспечивает высокое качество поиска, однако при увеличении объёма корпуса возрастают требования к памяти, времени построения индекса и стоимости отбора кандидатов. Одним из способов снижения вычислительных затрат является использование компактных бинарных представлений, получаемых из плотных эмбеддингов с помощью обучаемого хэширующего преобразования.

В репозитории реализована двухступенчатая схема поиска. На первом этапе документы и запросы сопоставляются в бинарном пространстве, что позволяет быстро отобрать ограниченное множество кандидатов. На втором этапе выполняется уточнение ранжирования на основе плотных векторных представлений. Такая организация системы позволяет исследовать компромисс между скоростью поиска, объёмом индекса и качеством ранжирования.

## Научная постановка

### Актуальность исследования

Семантический поиск является базовым компонентом интеллектуальных информационно-поисковых систем, систем поддержки принятия решений, вопросно-ответных систем и систем генерации с извлечением знаний. При работе с крупными корпусами существенное значение приобретают методы сокращения стоимости поиска без критического ухудшения качества. В этом контексте особый интерес представляет сочетание плотных представлений текста с компактными бинарными кодами, пригодными для ускоренного отбора кандидатов.

### Объект исследования

Гибридные системы семантического поиска по текстовым коллекциям.

### Предмет исследования

Методы построения и применения адаптивных бинарных кодов поверх плотных векторных представлений текста в задачах отбора и ранжирования документов.

### Цель

Создание воспроизводимого программного прототипа гибридной системы семантического поиска, обеспечивающего подготовку данных, обучение хэширующего модуля, построение индекса, выполнение поисковых запросов и оценку качества на реальных наборах данных.

### Исследовательская гипотеза

Если использовать обучаемый бинарный хэширующий модуль поверх плотного энкодера текста, то можно организовать быстрый отбор кандидатов при сохранении приемлемого качества поиска за счёт последующего повторного ранжирования в плотном пространстве признаков.

## Архитектура системы

Система построена как последовательный вычислительный конвейер:

1. Нормализация и предварительная обработка текста.
2. Построение плотного векторного представления документа или запроса.
3. Преобразование плотного вектора в бинарный код.
4. Индексация документов в бинарном пространстве.
5. Отбор кандидатов по бинарному сходству.
6. Повторное ранжирование найденных кандидатов по плотным векторам.
7. Расчёт показателей качества.

### Формальная схема

Пусть `x` обозначает текст, `e(x)` — плотное векторное представление текста, а `h` — обучаемое хэширующее преобразование. Тогда бинарный код строится следующим образом:

```text
z = h(e(x))
b = sign(tanh(z))
```

Во время обучения используется непрерывная релаксация бинаризации, а также добавляется слагаемое, штрафующее отклонение выходов модели от бинарного состояния. На этапе поиска бинарные коды применяются для быстрого отбора кандидатов, а итоговое упорядочение документов выполняется в плотном пространстве признаков.

## Наборы данных и подготовка выборок

### Поддерживаемые наборы данных

В репозитории предусмотрена работа со следующими наборами данных:

- `AllNLI` — объединение корпусов `SNLI` и `MultiNLI`;
- `STS-B` — набор пар предложений с оценкой семантической близости;
- `QQP` — набор пар вопросов с разметкой дубликатов.

### Роль наборов данных в эксперименте

`AllNLI`

- используется преимущественно для формирования обучающих троек;
- позволяет строить пары семантически близких и далёких высказываний на основе отношений следования и противоречия.

`STS-B`

- используется для построения обучающих троек и оценочных запросов;
- положительные пары определяются по верхнему порогу семантической близости;
- отрицательные пары определяются по нижнему порогу семантической близости.

`QQP`

- используется как источник положительных и отрицательных пар вопросов;
- включается в обучающую выборку и оценочный набор.

### Форматы создаваемых файлов

После подготовки данных формируются следующие файлы.

`corpus.jsonl`

```json
{"id":"txt_001","text":"semantic search with transformers","metadata":{"datasets":["stsb"],"splits":["train"]}}
```

`train_triplets.jsonl`

```json
{"query":"semantic retrieval","positive":"semantic search","negative":"banana smoothie","source_dataset":"stsb"}
```

`val_queries.jsonl`

```json
{"query":"semantic retrieval","relevant_ids":["txt_001"],"source_datasets":["stsb"]}
```

`test_queries.jsonl`

```json
{"query":"duplicate question example","relevant_ids":["txt_010"],"source_datasets":["qqp"]}
```

### Схема разбиения данных

Вычислительный эксперимент строится по схеме:

- `train` — обучение бинарного хэширующего модуля;
- `validation` — подбор параметров и выбор конфигурации;
- `final test` — итоговая оценка качества.

Оценочный пул сначала формируется из размеченных данных, после чего детерминированно разделяется на проверочную и итоговую тестовую части с использованием параметров `holdout_fraction` и `seed`. Сведения о построенном разбиении сохраняются в `dataset_summary.json`.

## Модель и обучение

### Реализуемая модель

В системе реализована схема:

```text
текст -> энкодер -> плотный вектор -> HashingMLP -> бинарный код
```

Поддерживаются два варианта энкодера:

- `hashing` — быстрый детерминированный ориентир;
- `transformers` — энкодер на основе трансформерной модели, по умолчанию `sentence-transformers/all-MiniLM-L6-v2`.

### Функция потерь

Обучение включает:

- функцию потерь на тройках по прокси-метрике расстояния Хэмминга;
- штраф за квантизацию, приближающий выходы сети к бинарному состоянию.

### Ограничение реализованной схемы

В репозитории обучается бинарная хэширующая надстройка `HashingMLP`, тогда как текстовый энкодер используется в фиксированном режиме. Совместная сквозная донастройка полного конвейера `энкодер + хэширующий модуль` не реализована.

## Индексирование и поиск

Система поддерживает два режима поиска:

- `coarse_rerank` — предварительный отбор кандидатов в бинарном пространстве с последующим повторным ранжированием;
- `integrated_filtering` — режим поиска с дополнительной бинарной фильтрацией кандидатов.

Для индексирования доступны два вычислительных движка:

- `numpy` — базовая реализация без внешних библиотек;
- `hnswlib` — индекс на основе иерархического графа малых миров для приближённого поиска.

## Показатели качества

В репозитории рассчитываются следующие показатели:

- `Recall@k`;
- `MAP@k`;
- `nDCG@k`;
- `latency_ms`.

Указанные показатели позволяют одновременно оценивать полноту поиска, качество ранжирования и среднюю вычислительную задержку.

## Использование

### Просмотр интерфейса командной строки

```bash
./.venv/bin/python -m hybrid_search.cli --help
```

### Подготовка наборов данных

```bash
./.venv/bin/python -m hybrid_search.cli prepare-datasets \
  --output-dir data/real \
  --datasets allnli,stsb,qqp \
  --holdout-fraction 0.5 \
  --limit-train-rows 20000 \
  --limit-eval-rows 2000
```

Альтернативный запуск:

```bash
./.venv/bin/python scripts/prepare_datasets.py \
  --output-dir data/real \
  --datasets allnli,stsb,qqp \
  --holdout-fraction 0.5 \
  --limit-train-rows 20000 \
  --limit-eval-rows 2000
```

### Обучение бинарного хэширующего модуля

```bash
./.venv/bin/python -m hybrid_search.cli train-hash \
  --triplets data/real/train_triplets.jsonl \
  --checkpoint artifacts/hash_model.pt \
  --encoder-backend transformers \
  --transformer-model sentence-transformers/all-MiniLM-L6-v2 \
  --code-bits 128 \
  --epochs 5 \
  --batch-size 64 \
  --device cpu
```

### Построение индекса

```bash
./.venv/bin/python -m hybrid_search.cli build-index \
  --corpus data/real/corpus.jsonl \
  --checkpoint artifacts/hash_model.pt \
  --output-dir artifacts/index \
  --encoder-backend transformers \
  --transformer-model sentence-transformers/all-MiniLM-L6-v2 \
  --code-bits 128 \
  --index-backend hnswlib \
  --device cpu
```

### Выполнение поискового запроса

```bash
./.venv/bin/python -m hybrid_search.cli search \
  --index-dir artifacts/index \
  --query "semantic search with transformers" \
  --top-k 10
```

### Оценка качества поиска

```bash
./.venv/bin/python -m hybrid_search.cli evaluate \
  --index-dir artifacts/index \
  --queries data/real/val_queries.jsonl \
  --top-k 10
```

Сценарий выполняет:

1. подготовку наборов данных;

4. расчёт показателей качества на проверочной выборке;
5. расчёт показателей качества на итоговой тестовой выборке;

Типовая последовательность запуска на вычислительном кластере включает:

## Ограничения

Состояние репозитория характеризуется следующими ограничениями:

- совместная сквозная донастройка полного конвейера `энкодер + хэширующий модуль` отсутствует;
- автоматический выбор лучшей контрольной точки по проверочной выборке не реализован;
- механизм `integrated_filtering` представляет собой исследовательский вариант бинарной фильтрации, а не внутреннюю модификацию графового индекса;
- основное назначение репозитория состоит в проведении вычислительных экспериментов, а не в развёртывании промышленной поисковой службы.

- расширение набора функций потерь и сравнительных опытов;
- автоматизированный выбор оптимальной эпохи обучения;
- добавление полноценных сравнений с плотным поиском без бинарного этапа;
- расширение набора формируемых отчётов и сводных таблиц результатов.

## Заключение

Репозиторий представляет собой воспроизводимый исследовательский программный комплекс для изучения гибридного семантического поиска с адаптивным бинарным хэшированием. Реализация охватывает весь цикл вычислительного эксперимента: от подготовки данных и обучения до индексации, выполнения поиска, оценки качества и сохранения итоговых артефактов.
