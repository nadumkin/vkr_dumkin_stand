# Гибридный семантический поиск с адаптивным бинарным хэшированием

Программный прототип и экспериментальный стенд к ВКР «Гибридный метод
семантического поиска с адаптивным бинарным хэшированием на трансформерных
моделях» (НИУ ВШЭ, ФКН, магистерская программа «Системная и программная
инженерия», 2026 год).

---

## 1. Аннотация

Работа посвящена систематическому исследованию обучаемого бинарного хэширования
поверх замороженного трансформер-энкодера в задаче семантического поиска по
текстовым коллекциям и его количественному сопоставлению с классическими
методами сжатия векторных представлений (LSH, ITQ, PQ).

Разработан программный прототип гибридной системы поиска, объединяющий
плотные представления, обучаемый бинарный хэширующий модуль и графовый индекс
приближённого поиска HNSW. На корпусах из **224 017** и **645 893** уникальных
документов проведена серия экспериментов по архитектуре хэширующего модуля,
обучающему сигналу, совместному дообучению энкодера и ресурсной стоимости
итогового индекса.

Главные количественные результаты:

- архитектура хэширующего модуля — доминирующий фактор качества: диапазон
  `recall@10` между 10 ablation-конфигурациями достигает **19,6 п.п.** в
  бинарном режиме поиска (`binary_only`); критичны нормирующий слой
  `LayerNorm` и хотя бы один скрытый слой, тогда как глубина сверх одного
  слоя и тип нелинейности — второстепенны;
- в режиме `binary_only` обучаемый Distillation-MLP устойчиво **отстаёт** от
  аналитической ITQ-ротации на 1–3 п.п. на корпусах 200–650 тыс. документов;
  в режиме повторного ранжирования (`coarse_rerank`) различия методов
  становятся статистически незначимыми (recall@10 в коридоре 0,837–0,839);
- ресурсный анализ выявил контринтуитивный результат: при HNSW над бинарными
  кодами доминирующей по памяти структурой оказывается **сам граф**
  (≈ 287 МБ на 224 К документов при 256-битном коде), а не сжатые
  представления; единственной Парето-оптимальной точкой по памяти оказывается
  **PQ binary_only** (≈ 8 МБ).

## 2. Введение

### Проблематика

Семантический поиск на основе плотных векторных представлений обеспечивает
качество ранжирования, недостижимое для классических лексических подходов,
однако линейный рост объёма представлений с размером корпуса делает «голую»
схему «энкодер + точный поиск» нежизнеспособной на коллекциях масштаба
миллионов и десятков миллионов документов. На таких объёмах одновременно растут
требования к памяти, времени построения индекса и стоимости отбора кандидатов.
Стандартный ответ — приближённый поиск ближайших соседей (например, HNSW) и
методы сжатия представлений (LSH, ITQ, PQ, deep hashing), но их применимость
в гибридном поиске изучена неравномерно: в литературе сравниваются методы
поодиночке, без единого протокола, при разных стендах, наборах данных и
гиперпараметрах, что затрудняет содержательное сопоставление.

### Актуальность

Гибридный семантический поиск — базовый компонент современных корпоративных
поисковых сервисов, рекомендательных систем и систем генерации с дополнением
извлечённой информации (RAG). В каждом из этих сценариев баланс «качество ×
память × латентность» определяет техническую и экономическую целесообразность
внедрения. Систематический сравнительный анализ методов сжатия в едином стенде,
с фиксированными гиперпараметрами и единым протоколом оценки, позволяет
формулировать обоснованные операционные рекомендации, а не опираться на
эвристики, унаследованные от разрозненных публикаций.

### Цель

Разработать гибридную модель семантического поиска на основе плотных
представлений и адаптивного бинарного хэширования, обеспечивающую снижение
вычислительных затрат и затрат памяти при сохранении приемлемого качества
поиска.

### Задачи

1. Анализ современных методов семантического поиска, генерации плотных
   представлений, алгоритмов приближённого поиска ближайших соседей, а также
   методов сжатия и бинарного хэширования.
2. Выявление ограничений существующих подходов с точки зрения качества,
   масштабируемости, задержки и затрат памяти.
3. Формулировка требований к гибридной системе, сочетающей плотные и бинарные
   представления.
4. Разработка архитектуры гибридной модели (трансформер-энкодер + бинарный
   хэширующий модуль + HNSW-индекс).
5. Определение методов обучения бинарной модели, сохраняющих семантическую
   близость при переходе в пространство Хэмминга.
6. Реализация программного прототипа и экспериментального контура его оценки.
7. Экспериментальное исследование по метрикам качества, скорости и
   использования памяти.

### Объект и предмет

- **Объект**: гибридные системы семантического поиска по текстовым коллекциям.
- **Предмет**: методы построения и применения адаптивных бинарных кодов поверх
  плотных векторных представлений текста в задачах отбора и ранжирования
  документов.

## 3. Памятка по запуску основных экспериментов

Предполагается, что репозиторий клонирован, виртуальное окружение создано и
все зависимости установлены:

```bash
cd src
python3.10 -m venv .venv
source .venv/bin/activate
pip install -e .          # см. pyproject.toml
```

Все примеры запускаются из каталога `src/`. Эксперименты ориентированы на
ноутбук Apple MacBook Pro M4 Pro (16-ядерный GPU, 48 ГБ unified memory).

### 3.1. Подготовка корпусов

Корпуса собираются из AllNLI / STS-B / QQP через HuggingFace Datasets с
фиксированным `seed = 17`:

```bash
bash scripts/prepare_dataset.sh           # → data/real_300k/  (224 017 документов)
bash scripts/prepare_dataset_1m.sh        # → data/real_1m/    (645 893 документа)
```

Размер: `real_300k` ~120 МБ, `real_1m` ~310 МБ. Время: 5–10 / 15–25 минут.
Метаданные дублируются в `dataset_summary.json` каждого каталога.

### 3.2. Полная серия экспериментов (главы 4–5)

Полный воспроизводимый запуск всей экспериментальной серии:

```bash
caffeinate -i bash scripts/run_length_sweep_overnight.sh \
  > logs/length_sweep_$(date +%Y%m%d_%H%M).log 2>&1
```

Сценарий делает две фазы:

- **Фаза 1** (`real_300k`, ~5,5 ч): для длин кода 64/128/256/512 бит — обучение
  frozen Distillation v3 (8 эпох) + Joint v3 (2 эпохи) + сравнение с
  LSH/ITQ/PQ.
- **Фаза 2** (`real_1m`, ~3,75 ч): для тех же длин кода — оценка переиспользует
  модели, обученные в Фазе 1.

Между тяжелыми GPU-этапами включены 5-минутные паузы охлаждения.

### 3.3. Отдельные эксперименты

```bash
# Архитектурный ablation хэш-модуля (10 конфигураций, 256 бит)
.venv/bin/python scripts/run_hash_arch_grid.py \
  --data-dir data/real_300k --output-dir artifacts/hash_arch_grid_cb256 \
  --code-bits 256

# Сравнение методов сжатия для одной длины кода
.venv/bin/python scripts/run_baselines_comparison.py \
  --data-dir data/real_300k --output-dir artifacts/baselines/cb256_v3 \
  --code-bits 256 --pq-subspaces 32 --pq-centroids 256 \
  --distill-from-artifact artifacts/distill/cb256_v3_anneal_itqinit

# Одиночный запуск конфигурации Distillation v3 (frozen: annealing + ITQ-init)
.venv/bin/python scripts/run_distillation_training.py \
  --data-dir data/real_300k --output-dir artifacts/distill/cb256_v3_anneal_itqinit \
  --code-bits 256 --epochs 8 --batch-size 128 \
  --hidden-dims 768 --activation gelu --dropout 0.0 \
  --temperature 1.0 --temperature-end 10.0 --itq-init

# Joint-обучение энкодера + хэша
.venv/bin/python scripts/run_joint_distillation.py \
  --data-dir data/real_300k --output-dir artifacts/joint_distill/C_arch_annealing_itqinit \
  --code-bits 256 --epochs 3 --batch-size 128 \
  --encoder-lr 5e-6 --hash-lr 1e-3 \
  --hidden-dims 768 --temperature 1.0 --temperature-end 10.0 --itq-init
```

### 3.4. Сводные отчеты и графики

```bash
# Сводная таблица recall@10 с 95 % CI (нормальное приближение из агрегатов)
.venv/bin/python scripts/compute_recall_ci.py --out artifacts/recall_ci_summary.md

# Точные bootstrap CI (требует comparison.json с per-query метриками)
.venv/bin/python scripts/bootstrap_ci.py \
  artifacts/baselines/length_sweep_300k/cb*/comparison.json

# Все 8 рисунков глав 4–5 одной командой
.venv/bin/python scripts/figures/make_all.py     # → artifacts/figures/*.{png,pdf}

# Сводная таблица результатов длинового свипа
.venv/bin/python scripts/aggregate_length_sweep.py
```

## 5. Заключение

В работе решены все семь задач, поставленных во Введении. Реализован
программный прототип гибридной системы поиска, проведён систематический
эксперимент в едином стенде с фиксированными гиперпараметрами и единым
протоколом оценки.

**Научная новизна** определяется тремя экспериментально подтверждёнными
вкладами:

1. **Систематическое сравнительное исследование архитектур** обучаемого
   хэширующего модуля поверх замороженного трансформер-энкодера. На 10
   конфигурациях MLP показано, что архитектура является доминирующим фактором
   качества (разброс recall@10 — 19,6 п.п. в binary_only); критичными
   решениями оказались LayerNorm и наличие хотя бы одного скрытого слоя.
2. **Количественная характеризация условий применимости** обучаемого
   нейросетевого хэширования относительно классических методов: в режиме
   binary_only Distillation-MLP отстаёт от ITQ на 1–3 п.п. на корпусах
   200–650 тыс. документов, а в режиме переранжирования различия методов
   статистически незначимы.
3. **Полный ресурсный анализ** гибридной системы с разложением совокупной
   памяти по компонентам. Установлено, что при HNSW над бинарными кодами
   доминирующей структурой по памяти оказывается сам граф, а не сжатые
   представления, что количественно ограничивает применимость классической
   схемы «бинарный код + HNSW» при росте корпуса.

**Практические рекомендации** (Глава 5, раздел 5.9.3):

- при жёстком ограничении памяти — `PQ binary_only` (≈ 8 МБ vs ≈ 295 МБ
  у HNSW-методов на 224 К документов);
- при балансе качества и скорости — `ITQ + rerank` (recall@10 практически на
  потолке `dense_exact`, латентность ≈ 7 мс);
- при отсутствии требований к латентности — `dense_exact` без сжатия
  (простота реализации);
- обучаемые нейросетевые методы хэширования в нашей конкретной постановке
  (MiniLM-L6 + entailment-триплеты) не оправдывают сложности своей реализации.

**Ограничения и направления дальнейшей работы**:

- вариант «встроенной фильтрации» (бинарный код как фильтр-отсекатель внутри
  обхода HNSW) требует модификации C++ ядра `hnswlib` и вынесен в дальнейшую
  работу;
- совместное дообучение энкодера и хэш-модуля даёт нейтральный или слабо
  отрицательный эффект — гипотеза о необходимости существенно более
  информативного супервайз-сигнала (пары «запрос – релевантный пассаж» из
  MS MARCO / Natural Questions) и более крупных корпусов (10⁷+ документов)
  оставлена для дальнейших экспериментов;
- замена энкодера MiniLM-L6 на модели уровня DPR и исследование адаптивной
  длины бинарного кода — также в направлениях развития.
